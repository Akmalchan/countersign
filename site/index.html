What it checks

Fourteen questions a careful person would ask. Every time.

Each check is plain code with a formula, not an AI guess. Same bill in, same answer out, with the reason attached.

The bill8 checks · these set the risk score
The email3 checks

Sender authenticated (DMARC)

Did the inbox verify the email really came from that domain?

dmarc = fail → STOP

Mail signature (SPF / DKIM)

Was it sent by a mail server the domain actually authorizes?

spf ∨ dkim = pass

Reply-To matches sender

Would your reply secretly go to someone else?

domain(reply-to) = domain(from)
The document3 checks

Bank number checksum

Is the account number even valid, or made up?

"Real bank numbers have math built in. Fakes usually fail it."

IBAN mod 97 = 1 · ABA check digit

Line items vs total

Do the items actually add up to what you're asked to pay?

Σ items + tax = total ± $0.01

Document history

Was this PDF made the way this vendor's bills usually are, and edited after the fact?

"Every PDF remembers the software that made it."

PDF fingerprint = vendor's past bills

For developers

One call before any payment.

1
Send the bill

Raw email, PDF text, or fields you already parsed.

2
Get a stamp with proof

Risk, confidence, every check with its formula and evidence links.

3
Record the human's call

Approve, reject or "false alarm". Your weights adapt per company.

# check a bill before it's paid
curl https://api.countersign.dev/v1/check \
  -d '{"from":"billing@g00gle-cloud-billing.co",
       "vendor":"Google Cloud","amount":48250,
       "account_last4":"7730","invoice":"GC-90217"}'

{
  "stamp": "stop",
  "risk": 100, "confidence": 100,
  "checks": [
    { "id": "lookalike", "severity": "high",
      "why": "contains 'google' after 0→o, not google.com" },
    { "id": "bank", "severity": "high",
      "why": "••9021 → ••7730" }, ...
  ],
  "combos": ["lookalike + bank_changed"],
  "pay_allowed": false  // until a human signs
}
Command line

Put it in front of your payment run.

$
countersign check invoice.pdf

Check one or more PDF bills from the terminal.

$
countersign scan ./this-weeks-bills

Check every PDF in a folder before the weekly payment run.

$
countersign inbox

List the open bills waiting in the console.

Flags: --json for scripts, --strict to fail on HOLD too, --fresh to skip the lookup cache. It exits with code 2 if any bill is STOP, so a payment script can refuse to run. It never pays or approves anything.
